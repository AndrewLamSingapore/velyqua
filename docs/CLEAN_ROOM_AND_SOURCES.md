# VELYQUA Clean-Room and Source Policy

VELYQUA is an independent product. Publicly observable capabilities may be translated into abstract owner needs. Competitor expression must not enter the product.

This policy supports product and engineering discipline. It is not legal advice. Obtain Singapore counsel for name clearance, contracts, copyright, database rights, privacy and market-specific claims.

## Required conduct

- Record each public URL, access date, abstract capability and VELYQUA decision in the discovery source register.
- Rewrite a capability as an owner job before design begins.
- Create original labels, navigation, hierarchy, copy, illustrations, icons, colors and interactions.
- Create aquarium rules from documented evidence and qualified review.
- Record source type, citation, retrieval date, license status and reviewer for knowledge content.
- Run an originality and Apple Guideline 4.1 review before submission.
- Record licenses and attribution duties for every third-party package, asset and dataset.

## Prohibited conduct

Do not:

- copy code, copy, screenshots, visual hierarchy, catalog data, taxonomies, rules, prompts, data structures or interface details from a competitor;
- place competitor screenshots or traced layouts in VELYQUA design files;
- scrape catalogs, decompile software, intercept traffic, bypass controls or use private endpoints;
- import competitor binaries, response payloads, proprietary datasets or prompt systems into the repository;
- create accounts or gather data contrary to published terms; or
- treat a public feature claim as evidence that VELYQUA may copy its implementation.

## Public source register

The following source classes informed the v2 boundary and validation plan. Exact URLs, access dates, licensing notes and abstract jobs must be maintained in the controlled discovery register before an item is used in product content.

| Source | Purpose | Use boundary |
|---|---|---|
| TankForge public product website | Public capability and platform claims | Capability benchmark only; no copied expression or data |
| TankForge public methodology | Published statements about facts, rules, heuristics, confidence and limits | Trust benchmark only; VELYQUA rules remain original and reviewed |
| TankForge public Pro information | Public packaging and workflow claims | Market context only; no pricing or feature-copy obligation |
| TankForge App Store listing | Public iOS capability and release claims | Platform benchmark only |
| Apple App Review Guidelines | Completeness, privacy, safety and copycat review context | Review against the current official version before submission |
| Intellectual Property Office of Singapore copyright overview | General Singapore copyright context | Obtain counsel for project-specific questions |
| Singapore AVS ornamental-fish guidance | Personal import, commercial licensing, prohibited species and CITES context | Link to official current guidance; never claim legal clearance for an owner |
| Singapore PUB water-quality information | Source-water context | Never assume the value in a specific home or aquarium; require owner measurement |
| Singapore PDPC data-protection obligations | PDPA operating context | Legal and privacy review remains required |
| CITES Trade Database | International wildlife-trade context | Interpretation requires qualified review |
| Kew Plants of the World Online | Candidate plant taxonomy source | Product use requires citation and license review |
| OWASP MASVS | Mobile security verification | Use as a baseline, not proof of security by itself |
| W3C WCAG 2.2 and Apple accessibility guidance | Accessibility review | Combine automated and real-device manual testing |
| Expo, React Native and Supabase official documentation | Implementation and platform behavior | Verify against the versions used in the repository |

Aquarium-care content needs its own evidence and reviewer record. A benchmark or platform source cannot substitute for animal-care review.

## Source-record fields

Each controlled source record must contain:

- source title and publisher;
- public URL or formal citation;
- access or publication date;
- source type and jurisdiction;
- abstract owner need or factual claim supported;
- VELYQUA decision;
- license and attribution status;
- reviewer and review date;
- expiry or recheck date where facts may change; and
- correction or withdrawal status.

## Repository hygiene

Do not commit:

- raw historical product documents as the active specification;
- competitor screenshots, binaries or scraped material;
- private founder photographs or real owner records without explicit permission;
- commercial negotiations, vendor quotes or unapproved pricing experiments;
- `.env`, service-role keys, private API keys, signing credentials or access tokens;
- ZIP checkpoints, `node_modules`, `.expo`, `dist` or generated build artifacts; or
- third-party assets without documented permission and attribution.

Stable public decisions belong in Markdown. Delivery truth belongs in code and tests. Sensitive records remain in their controlled private systems.

## Handoff checklist

- Founder, designer, developer and content leads acknowledge this policy.
- Each benchmark item maps to an abstract owner need and public source.
- Design files contain no competitor screenshots, traced layouts, copied copy or imported assets.
- The repository contains no competitor binary, payload, catalog, prompt, schema or proprietary dataset.
- Third-party packages, media and datasets have recorded licenses and attribution duties.
- Branding, copy, screenshots, navigation and interaction receive an originality review.
- Counsel reviews the final name, terms, privacy position, contracts and disputed IP questions.
- GitHub, design, Apple, Expo/EAS, Supabase, domain, monitoring and support accounts remain founder-controlled.
- Architecture, migrations, rule fixtures, runbooks and restore instructions are current before release.
